# Редакция @trygta

Сервер запускает /opt/trygta/bot.py через systemd. Входящие порты боту не нужны. Конфигурация хранится в /etc/trygta.env с правами 0600, очередь и решения редактора — в /var/lib/trygta/queue.db.

## Подключение

1. Создайте отдельного бота через @BotFather. Откройте его в личке, нажмите Start и добавьте администратором @trygta с правом публикации.
2. Заполните BOT_TOKEN, OWNER_ID (числовой ID вашего личного Telegram), APIFY_API_TOKENS и RIVER_API_KEY в /etc/trygta.env. Ключи Apify перечисляются через запятую. По умолчанию используется deepseek-ai/DeepSeek-V4.1-Flash. Для смены модели задайте DEEPSEEK_MODEL.
3. Выполните systemctl restart trygta.service и проверьте systemctl is-active trygta.service. В личке отправьте /status. Ошибки подключений выводятся командой journalctl -u trygta.service -n 50. В журнал пишутся имя операции, тип ошибки и HTTP-код.
4. Проверьте первый живой черновик. Нажатие «Опубликовать» сразу отправляет его в канал.

## Отбор

Xquik проверяет посты за последние 12 часов через Apify. Каждый третий запрос выбирает популярные посты в этом окне, остальные — самые новые. Четыре выборки из пяти тематические, пятая охватывает все темы GTA VI. При девяти ключах интервал 200 секунд, при десяти — 180 секунд. Проверка расписания каждые 20 секунд. До десяти результатов за запуск. Метрики обновляются при повторном появлении поста. Дубликаты по ID и тексту объединяются. Модератор получает максимум одну карточку за 15 минут.

Перед запуском бот сверяет тариф Free и расход за расчётный цикл аккаунта. При остатке меньше пяти центов переходит к следующему ключу. Задание и резерв записываются в SQLite. Лимит событий актёра за запуск $0,0015, предварительный резерв с инфраструктурой $0,003. После завершения резерв заменяется расходом Apify с запасом $0,00005. Бот ограничивает каждый ключ суммой $4,95 за цикл и всю очередь суммой $4,95 на ключ за скользящие 31 день. River оплачивается отдельно.

У каждой карточки есть рубрика, заголовок, короткий перевод, ссылка на оригинал и первое прикреплённое фото, если оно доступно. Кнопки действуют только в личке владельца. При одобрении бот копирует уже просмотренную карточку в канал. Старые черновики в личке можно отклонить.

## Восстановление после сбоя

Если Telegram мог принять публикацию, но соединение оборвалось до подтверждения, запись получает состояние uncertain. Бот блокирует повторную отправку. Администратор сверяет содержимое канала и запись SQLite по ID поста X. Если публикации действительно нет, можно вернуть именно эту запись из uncertain в review и заново нажать кнопку. Состояние rejected окончательное. При смене ключей перезапустите службу.
